# Produce Static Ads

## Scope and ownership
Own the general static production workflow, including designed brand swaps, UAM batches and revisions. This skill packages Sis's documented production knowledge, not a claim that every heuristic has proven performance.
Handle copy strategy, competitor discovery, specialized visual styles and media buying as separate workstreams. Use approved guidance available in the receiving environment. No other skill or OpenClaw tool is required to read or use this procedure. Producing an asset does not authorize publishing it.

## Intake and truth
Resolve product, audience, single argument, exact approved copy, offer, placement, count, deadline, reference intent and requested delivery route. Carry existing authorization forward. Read the supplied brand brief, approved assets, prior feedback and current restrictions before brand work.
Build a source-backed truth card: product forms and counts, exact packaging, allowed claims/proof strings, offer and destination, logo, and design system. Mark unknown facts instead of inventing them. Verify current official branding where it can supersede cached guides.
For copy development, evaluate: awareness fit, one argument, concrete visual proof, brand specificity and two-second comprehension. Do not silently rewrite approved copy during production.

## Reference contract
For each reference-led row, bind:
1. Source skeleton to preserve: canvas, major zones, text/product bounding boxes, type-scale ratios, whitespace, focal order, crop and lighting.
2. Source content to discard: competitor brand, claims, testimonials, badges, guarantees and unauthorized offers.
3. Product constraints: canonical image, permitted product forms/count, scale and physical contact with the scene.
A shared concept is not reference fidelity. Feed the actual source image as the per-row image reference. Never substitute a verbal description or generic house template without labeling it a diagnostic proof.
Use fresh aspirational refs when requested. Make the final pack traceable to the actual refs used.

## Product and generation preflight
Validate reference files exist, have real image bytes, useful resolution, visible product and readable canonical label. The visual product authority must contain only allowed product forms. A sachet-only row cannot use a box-plus-sachet authority.
Select the correct SKU explicitly for multi-product brands. Lock package, label, logo and approved copy independently of layout.
Use an image-generation or image-editing tool available in the receiving environment. This package is a procedure, not an image-generation service or a bundled implementation. Supply the actual reference and canonical product images to a tool that supports image references; if none is available, report the missing capability instead of pretending to generate.
Default designed feed output is native 1080x1350, 4:5, unless the brief specifies another size. Do not generate a tall master and silently crop it as a substitute.
Before paid submission, verify the tool's current capabilities, configure credentials privately, and define a spend ceiling, retry ceiling, immutable row IDs and expected outputs. Never place credentials in prompts, packages or logs.
For long runs, persist job IDs, owner, row state, provider receipts and restart checkpoints using the receiving environment's job system. Verify actual job state before claiming it is running.

## Proof, batch and stopping rules
Start with a small real proof when the direction is untested. Do not expand beyond the approved scope. Waves above eight require review between waves, each wave at most eight.
Record a row matrix with reference, canonical product, locked copy, placement, prompt, provider/model, output and QA status. Diversify actual visual structures, not just headline wording.
After two failed rounds with the same strategy, stop unchanged paid repairs. Record the repeated fingerprint and materially change the strategy within existing authorization, or report the blocker.
Repeated package-redraw corruption calls for an exact-product assembly route or a materially different generation strategy, not a third identical prompt attempt. Deterministic assembly must preserve the actual approved reference structure, not replace it with a generic template.

## Revision mode
Start from the approved canonical source, not a failed derivative. Reconcile the latest feedback with all preservation and exact-copy fields; remove rejected elements from positive instructions.
For copy-only or headline-only edits, use the tool’s genuine masked or region-constrained edit mode with the approved master as the source. Bind the edit rectangle, source/candidate hashes and outside-zone drift evidence. Verify the tool actually supports constrained edits; the word "surgical" in a prompt is not a capability.
Fail on material changes outside the authorized zone. If true surgical mode still redraws frozen content, stop that route and rebuild once from the clean accepted base with final copy bound initially; evaluate exact copy, product fidelity, typography and accepted structure rather than claiming pixel identity.

## Independent QA
Review the actual final image at original resolution, not just a thumbnail or automated score. Keep these gates independent:
- Exact approved copy, once, in order, without invented badges or unsupported proof.
- Correct SKU, forms/count, canonical package, label words and logo.
- Reference skeleton and brand typography/color fidelity.
- Readable hierarchy, one argument, physical scene logic and full-bleed requested geometry.
- Exact requested coverage, unique IDs and contact-sheet diversity.
Automated product/text QA is diagnostic, not authority for readable package microcopy or surgical preservation. Reject out-of-range numeric scores. Never let a high aggregate score override a critical gate.
Review the whole contact sheet for omitted, duplicated or reordered words, repeated layouts and missing rows. Compare source beside output. Repair only flagged rows within the bounded contract, then rebuild and recheck the contact sheet.
Do not claim measured creative performance without actual results.

## Delivery contract
Provide final native-resolution files, a contact sheet, source-versus-output review sheet for reference work, and a manifest with row IDs, source/ref paths, canonical product paths, locked copy, final hashes/dimensions, model/tool, QA verdicts and unresolved failures.
Separate passed finals from diagnostics and failed candidates. Report requested/passed/blocked counts honestly. A process exit or local file does not prove delivery.
Follow the current approved upload/send route and verify its receipt. Creation does not authorize third-party distribution. Keep client-confidential material and secrets out of a reusable shareable package.


## Portable working record
For each row record: ID; approved copy verbatim; single argument; reference file; product file and SKU; preserved layout zones; allowed changes; output size; tool/model; job ID; cost; attempt count; final file and SHA-256; copy/product/layout/geometry QA; final verdict and blocker.
Keep final files, comparison sheets and the working record together. Do not include private briefs or third-party assets in public repositories.
